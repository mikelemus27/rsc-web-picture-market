# Backend server port from `PORT` env (fallback 4001)

- **Date**: 2026-10-10
- **Branch**: `chore/dev-backend-port-from-env` (from `dev` @ `c4fe304`)
- **Tracks**: GitHub issue #43; `TODO.md` → *Use `process.env.PORT` for backend server port*
- **Lane**: FTD (one doc, then tasks against observed proof)

## Intent

`_01_rsc_wpm_backend/src/index.ts` hardcoded `port: 4001` in `Bun.serve`, so the service could
not be told which port to listen on per environment (deployment, CI, local) — unlike `DB_PORT`,
which `src/infraestructura/database/postgres.ts` already reads with `Number(process.env.DB_PORT)
|| 5432`. The goal: the same env-with-fallback pattern for the server port, without changing
the default (4001) so local runs and the Compose mapping keep working untouched.

## Scope

### In
- `src/index.ts`: `port: 4001` → `port: Number(process.env.PORT) || 4001` (one line, same shape
  as the existing `DB_PORT` line).
- New `test/server-port.test.ts`: spawns `src/index.ts` with `PORT=45991`, polls `GET /health`
  on that port, asserts any HTTP answer (200 or 503) — proves the listener honours `PORT`.
- `BackEnd_README.md`: env-table `PORT` row default `3000` → `4001` (the row was stale: the API
  has listened on 4001 since long before; leaving `3000` would contradict this change).
- `TODO.md`: move the item to `## Completed` with evidence.

### Out
- No change to the default port when `PORT` is unset (4001 — covered by the whole existing API
  suite, which targets `http://localhost:4001`).
- `commands.md` note ("El puerto 3000 es histórico: la API escucha en 4001") stays — it is
  already accurate.
- Frontend stack untouched: `_02_rsc_wp_frontend` keeps its own `.env` and `API_URL`; making the
  port flow to the frontend is a separate pass.
- `_01_rsc_wpm_backend/.env` (a stale duplicate of the root `.env`) is left as-is; the backend
  compose does not read it.

## Extension — `PORT` single source (root `./.env`)

Review feedback: `PORT` must have ONE home, not six (the override hook alone left the literals
scattered). Root `./.env` is already the repo's canonical env file — generated by
`project-tools/rotate-db-secrets.sh` (`write_env_file`) and read by local tools
(`db-healthcheck.sh`) — so `PORT` lives there and everything derives from it.

- `project-tools/rotate-db-secrets.sh`: new `PORT="${PORT:-4001}"` config; `write_env_file` emits
  `PORT=$PORT` (so it survives rotation); `HEALTH_URL` default now uses `${PORT}`.
- `_01_rsc_wpm_backend/docker-compose.yml`: backend mapping → `${PORT:-4001}:${PORT:-4001}` and
  `environment: PORT: ${PORT:-4001}` — the host mapping and the in-container listener move
  together from the same value.
- `project-tools/container-management.sh`: reads `PORT` from root `./.env` and exports it, so
  `docker compose` interpolation and the local test runner agree without extra CLI flags.
- Tier 2 (so a changed port does not silently break the suites): `test/usuarios.backend.api.test.ts`,
  `run-backend-tests.ts`, and `package.json` (`test:full`/`test:tdd`) now default to
  `process.env.PORT ?? 4001` / `${PORT:-4001}`.
- `env.template`: documents `PORT=4001`.
- `src/index.ts` keeps the `|| 4001` fallback, so a bare `bun run index.ts` with no `.env` still
  works.
